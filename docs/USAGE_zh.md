这份指南按界面逐屏讲：点哪里、每个字段是什么、你的数据会发生什么。

## 🚀 一、启动

```bash
# Windows：setup.bat  →  start.bat
# macOS/Linux：./setup.sh  →  ./start.sh
```

浏览器会自动打开 `http://127.0.0.1:<端口>`。端口默认随机，记在 `data/.last_port` 里；想固定用 `PORT=31200 python -m app.main`。

首次启动会创建 `data/`（数据库 + 照片目录）。所有东西都在本机，不上传、不联网（底图瓦片除外）。

> 🖥 **安装版 / 绿色版**：如果是从 Release 下载的，不需要上面这些步骤——双击 `FoodieTrail.exe`
> （或桌面快捷方式）即可。不会弹黑窗口，浏览器自动打开，程序常驻托盘，`data/` 就在 exe 旁边。
> 界面与数据格式和源码版完全一致。

## 🧭 二、三个视图

顶栏在 **地图 · 清单 · 看板** 之间切换，右侧依次是搜索、**添加**、**更多**。

| 视图 | 用来做什么 |
| --- | --- |
| 🗺 **地图** | 按空间浏览：聚合、按评分着色的图钉、悬停预览 |
| 📋 **清单** | 筛选、排序、对比、批量删除 |
| 📊 **看板** | 看整体口味分布，再从任意图表下钻 |

---

## 🗺 三、地图

- **图钉颜色**按评分：灰（≤ 2）、蓝（3）、橙红（≥ 4）；缩小地图时相邻图钉自动聚合成气泡。
- **悬停**图钉或清单卡片 → 弹出小卡，显示店名、星级、状态、人均与前三个标签；清单侧悬停时地图会同步高亮。
- **点击**图钉 → 打开详情卡片，地图飞到该点。
- **点击**聚合气泡 → 弹出该区域的美食清单（最多 60 条），点条目打开详情。
- **右键**地图（桌面）或**长按**（移动端）→ 直接打开新增表单，坐标已填好。
- **定位我**（在新增表单里）调用浏览器定位，后端把 WGS-84 转成 GCJ-02，并在地图上放一个临时标记。

> 没配高德 Key？会用 Leaflet + 高德栅格瓦片，并显示提示条说明地址搜索不可用。图钉、筛选、编辑照常。

---

## 📋 四、清单

- **搜索框** —— 匹配店名、备注、标签，250 ms 防抖。
- **筛选栏** —— 状态 chips、排序、带角标的筛选按钮，以及每个已生效条件对应的可删除 chip。
- **排序** —— 最近更新 / 评分最高 / 人均最低 / 店名。
- **滚动加载** —— 每批 60 条，接近底部时追加；1000 条也不会一次性塞进 DOM。
- **悬停卡片** —— 地图上弹出该店预览（地图不会移动，不会跟着鼠标乱飞）。
- **多选** —— 从「更多」进入选择模式，支持**全选**（当前筛选结果，不只当前 60 条）、**反选**、**清空**；**删除**一次请求删完。
- **键盘** —— `↑`/`↓` 移动高亮，`Enter` 打开，`Esc` 关闭清单。

## 📊 五、看板

一屏 12 组聚合：总记录、打卡率、待拔草、人均均值与中位数、状态构成、评分分布、价位分布、高频标签、近 12 个月趋势、照片覆盖、数据健康度，以及两个「接下来吃什么」清单。

**每张图都是筛选器。** 点击效果：

| 点击对象 | 结果 |
| --- | --- |
| 状态扇区 | 清单按该状态筛选 |
| 某根星级柱 | **精确**星级（4 星就是 4 星，不是 ≥ 4） |
| 价位档 | 该档区间，上限开区间 |
| 标签条 | 该单个标签 |
| 行动清单里的某条 | 直接打开详情 |

下钻会先清掉遗留的关键词 / 标签 / 草稿 / 视野条件，并把草稿范围设为**不含草稿**——因为看板本身就不统计草稿。这样「4★ = 42」点进去还是 42 条。

## ➕ 六、新增 / 编辑记录

### 6.1 必填

- **店名** 和 **位置**。位置可以来自：选点模式点地图、右键 / 长按、地址搜索、定位我。坐标 `0,0` 是合法位置。

### 6.2 选填（「补充信息」里）

| 字段 | 说明 |
| --- | --- |
| 星级 | 1–5，决定图钉颜色 |
| 标签 | 输入 + `Enter`；最多 32 个、每个 24 字，重复自动忽略 |
| 营业时间 | 按周设置，一天最多 6 个时段；全部为空 = 休息；编辑器写结构化 JSON |
| 人均 | 整数，`0` 表示免费（不是「未知」） |
| 打卡状态 | 想去 / 去过 / 收藏 |
| 备注 | 自由文本 |
| 照片 | 最多 9 张，可一次多选 |

### 6.3 照片

每张都会按 EXIF 校正方向、长边缩到 1280 px、重编码为 JPEG（质量 82，必要时降到 30，直到 ≤ 500 KB）。不保留原图——这是个人记录，不是图库。

### 6.4 保存与失败处理

- 表单先在本地校验（店名、位置、照片数量），错误提示在对应字段下方。
- 保存顺序：先存记录，再逐张传照片。**照片失败时记录已保存、失败的那张留在表单里、表单不关闭**——再点保存只重试这一张。
- 删除已有照片是「标记待删」；删除失败会留在列表里让你重试，而不是悄悄保留一张你以为删掉的图。
- 新建成功后的 toast 带「再记一家」，连续打卡不用多点。

### 6.5 草稿

- 勾选「存为草稿」后，这条不进看板，列表里带角标。
- 新增表单还会把没提交的内容自动存进 `localStorage`（400 ms 防抖）；关掉标签页再打开能恢复，并提示有几张照片需要重新选择。
- 草稿可见范围是一档三态：**全部 / 不含 / 仅草稿**，清单与地图用同一档，不会出现「列表有、地图没有」。

## 🍽 七、记录详情

- 以卡片形式浮在地图上方；如果清单开着，会自动把对应行滚进视野并高亮。
- **状态分段控件** —— 想去 / 去过 / 收藏，一点即存（乐观更新，失败回滚）。
- **导航** —— 新标签页打开高德标记页（不配 Key 也能用）。
- **编辑** —— 会先取完整记录（清单接口只带一张封面），所以照片不会「打开表单就消失」。
- **照片** —— 灯箱浏览，`←`/`→` 翻页，`Esc` 或点背景关闭。
- **删除** —— 二次确认后删除记录及其照片文件。

## 🔍 八、筛选用法

| 条件 | 语义 |
| --- | --- |
| 关键词 | 匹配店名 / 备注 / 标签，`%` 与 `_` 按字面量处理 |
| 星级 | 选 4–4 是精确区间；只设下限就是「≥ N」 |
| 人均 | `<30`、`30–60`、`60–100`、`100–200`、`≥200`，**下限含、上限不含** |
| 标签 | 全部匹配（默认）或任一匹配 |
| 状态 | 想去 / 去过 / 收藏 |
| 视野 | 只看当前屏幕范围，平移缩放后自动刷新边界 |
| 草稿 | 全部 / 不含 / 仅草稿 |

几个要点：

- 筛选面板是**草稿态**：改动只更新面板里的副本并本地估算「符合 N 家」，点**应用**才真正发一次请求。
- 已生效的条件显示为 chips，可逐个移除；**清除全部**会连关键词一起清。
- 条件写进 URL（`?rating=4&tags=火锅&drafts=hide`），刷新、收藏、前进后退都不丢。
- `Esc` 逐层关闭（确认弹窗 → 选点 → 选择模式 → 筛选面板 → 详情 → 清单），并同步 URL。

## 💾 九、导出 / 导入

### 9.1 导出

「更多 → 导出备份」，后端出两种 JSON：

| 模式 | 照片 | 适用 |
| --- | --- | --- |
| `full` | base64 内联 | 真正的备份、换机器 |
| `meta` | 不带，`photosIncluded: false` | 只要数据、不要照片 |

默认含草稿，且当前筛选仍然生效——想导全部，先清空搜索和筛选。

### 9.2 导入

1. **选文件** → 后端先校验并返回预览：*新增 N、更新 M、无效 K*。
2. **确认** → 开始写入，有实时进度（上传阶段不确定进度，之后按条数 60%→100%）。
3. 结果会报：写入、**已是最新未覆盖**、失败、无效、跳过异常照片、保留原有照片、id 重建。

内置的安全规则：

- 每条记录一个事务；单条失败计入 failed，整批继续。
- 备份里的照片先解码、校验字节与像素、重编码，**全部通过了才动数据库**。某条里有一张坏图 → 这条保留原有照片。
- 不带照片的备份（`meta`）绝不会清空库里已有的照片。
- `updatedAt` 更旧的记录跳过并单独计数——「写入 0 条」是正常结果，不是报错。
- 不能放进 URL 的 id（含 `/`、空格）会确定性重建，同一份文件导两次不会产生重复记录。

## ⚙️ 十、设置

「更多 → 设置」管理可选的高德集成：

| 字段 | 用途 |
| --- | --- |
| JS API Key + 安全密钥 | 浏览器里的地图 SDK |
| Web 服务 Key | 后端代理：POI 搜索、地址解析、驾车路线 |

- 已保存的值掩码回显；输入框留空 = 保持原值。
- 「测试连接」会真的问一次高德，验证已存的 Key 是否有效。
- 「清除安全密钥」只删 `securityJsCode`；「全部清除」删所有 Key，都要确认。
- 保存 Key 后会整页刷新——地图 SDK 一个页面只能初始化一次。

### 10.1 检查更新

「更多 → 设置 → ④ 关于与更新」显示当前版本、这一份是怎么装的、以及有没有新版本。

- **启动时检查更新**默认开启：每次打开向 GitHub 查一次（结果缓存 30 分钟），有新版本就在工具栏下方出一条**不打断操作**的提示条；点 ✕ 忽略该版本，下个版本发布后会再提醒。
- 这个检查会把本机 IP 暴露给 GitHub。介意就关掉开关，手动「检查更新」照常可用。
- 失败时只有设置面板里一行灰字，启动时什么都不会弹。提示语**永远是一句中文**（原因 + 等多久 + 去哪看），不会把 GitHub 的英文报错原文甩出来。
- 联网方式会**依次尝试直连与 Windows 系统代理**（读注册表，不只是环境变量），哪条能通用哪条。只用直连，那些只有代理才能出站的网络（公司内网、校园网）一次也连不上；只用代理，`api.github.com` 常因代理出口是共享 IP、额度被别人用光而返回 403。企业网络里代理会拦截时，设环境变量 `FOODMAP_UPDATE_NO_PROXY=1` 强制直连。

**安装版**——「下载并安装」会在后台拉 `setup.exe`，用 Release 元数据里的 size 与 SHA-256 复核，然后退出程序、静默安装、自动重新打开。`data/` 全程不动。安装包没有代码签名，Windows 可能弹一次 SmartScreen，点「更多信息 → 仍要运行」。下载失败会换另一种联网方式重试；都不通就用「复制下载链接」，拿浏览器或下载工具自己拉。

下载途中按钮旁会出现「**取消下载**」：点下去立刻变成「取消中…」，后台停掉连接、删掉半截的 `.part`，最后落到「已取消下载」——**不会**报成「下载失败」，也不会留下半个安装包。取消后随时可以再点「下载并安装」重新开始（不支持断点续传，是整包重下）。下载中不允许安装，避免装到半个包或静默装回旧版同名 exe。

**绿色版 / 源码版**——**故意**不开放自动安装：在这两种形态里跑 `setup.exe` 会在 `%LOCALAPPDATA%` 下**再装一份**，而不是升级你正在用的这份。界面给的是「前往 Release 页面」；下载后把 `FoodieTrail.exe` 与 `_internal\` 覆盖过去，**绝不要覆盖 `data\`**。

## 🩺 十二、保持数据健康

```bash
python health_check.py          # 只读体检
python health_check.py --deep   # 额外逐张解码照片
```

检查项：SQLite 完整性、表结构、字段越界、照片文件缺失或 0 字节、孤儿文件、加密钥匙、WAL 大小、是否混入演示数据。退出码 0 = 无致命问题，1 = 需要处理。

做任何批量操作前，把 `data/` 整个目录复制一份——这一个目录就是整个应用。

## ❓ 十三、常见问题

**地图一片空白。** 底图瓦片需要联网；没配高德 Key 时地址搜索本来就不可用。

**地址搜索是灰的 / 提示要 Key。** 这个功能要 **Web 服务**类型的 Key，和 JS API Key 不是同一个。

**某条记录不见了。** 看筛选 chips——搜索、标签、状态、视野、草稿是叠加的；`Esc` 或「清除全部」可复位。地址栏里就是当前条件。

**编辑后有些字段被我「改」没了。** 更新接口是整体替换；界面每次发全字段，只有手写脚本会遇到。脚本请 `GET` → 改 → 整体 `PUT`。

**照片比原图糊。** 设计如此：长边 1280 px、≤ 500 KB。想要更高画质，改 `app/pathconf.py` 里的 `PHOTO_MAX_EDGE` / `PHOTO_QUALITY` 再传。

**看板数字和清单对不上。** 看板从不统计草稿；清单按你的草稿范围走。从图表下钻时会把范围设为「不含草稿」，两边就一致了。
